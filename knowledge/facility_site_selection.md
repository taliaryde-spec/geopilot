# GeoPilot 公共设施候选选址方法

本文档定义 GeoPilot 演示项目的候选选址口径，用于把公共服务覆盖结果转化为可解释的候选区域和排序依据。它不是法定规划标准，也不包含真实土地审批结论。真实选址必须结合当地规划、权属、生态、安全、交通和公众参与要求，并由具备相应职责的专业人员复核。

## 使用边界与分析目标

候选选址的目标是从当前社区覆盖结果中识别“值得进一步调查的位置”，而不是自动决定新建设施的最终位置。输入至少需要经过验证的 `coverage_ratio`、`population`、`demand_score` 和社区几何；如果还要判断实际可达性，需要道路网络、出入口和交通方式。如果要判断建设可行性，还需要土地利用、规划用途、权属、地形、水域、生态保护、灾害风险和现状建筑等约束图层。

候选点不是最终建设位置。GeoPilot 输出的点可以代表未覆盖社区的几何内部点、人口或需求加权中心、可用地块代表点，或者外部候选点数据中的一个要素。几何质心可能落在凹多边形外部，因此默认应使用保证位于面内的代表点；但代表点只保证几何位置关系，不代表该位置存在道路、空地或建设条件。报告必须披露候选点生成方式和缺失数据，不能把“分析优先级”表述为“建设许可”或“最终选址”。

## 候选点生成、硬约束与排序流程

完整流程采用“先约束、后评分、再做敏感性检查”的顺序。第一步从已经验证的社区覆盖结果生成初始候选集合。可将 `coverage_ratio` 低于业务阈值的社区视为服务缺口区域，再为每个缺口社区生成一个面内代表点；如果用户提供了候选地块或现有公共用地，应优先从这些真实候选要素中筛选，而不是凭空创建建设位置。初始集合必须保留 `neighborhood_id`、覆盖率、人口、需求分和候选来源，确保结果可以追溯回社区与输入数据。

第二步执行硬约束过滤。硬约束表达“违反后不能进入排序”的条件，例如候选点不得位于水域、生态保护范围、危险源缓冲区或明确禁止建设的规划用地内，也可以要求候选点必须落在指定行政范围或允许用地中。距离阈值必须在适用米制 CRS 下计算。缺少约束图层时，系统不能假设候选点自动通过，只能把对应检查标记为 `not_evaluated`，并在报告中列为阻断真实决策的资料缺口。硬约束和偏好评分必须分开；不能用一个较高需求分抵消违反禁止建设条件的问题。

第三步为通过硬约束的候选点计算可比较指标。服务缺口可定义为 `service_gap = 1 - coverage_ratio`，合法范围是零到一；`demand_score`、`population`、到现有设施的距离和可达性等指标量纲不同，组合前必须说明归一化方法、方向和缺失值处理。对于“值越小越好”的指标应先转换方向。例如到道路入口的距离通常越短越好，不能与“距离现有同类设施越远可能减少服务重叠”混为同一个距离偏好。极端值会影响 min-max 归一化，真实项目应检查分布并考虑分位数截断或稳健缩放。

演示排序可以使用透明的线性加权公式：`candidate_score = 0.45 * service_gap + 0.30 * demand_norm + 0.20 * population_norm + 0.05 * accessibility_norm`。权重之和必须为一，每个分量必须位于零到一。该公式只用于展示可解释的多指标排序，权重不是由现行规范或利益相关者协商得到，因此不能宣称具有普遍最优性。若没有道路或可达性数据，不应把 `accessibility_norm` 猜成某个值；应删除该项并重新归一化剩余权重，或者明确把排序标为不完整。

第四步处理空间公平与重复服务。候选点不能只按 `demand_score` 从高到低选择，因为高需求社区可能已经具有较好覆盖，也可能多个高分点集中在同一区域。可以在选出一个候选后，更新其潜在服务区或对邻近候选施加距离惩罚，再选择下一个点；这属于迭代选址或最大覆盖问题。当前 GeoPilot 的 v0.1 覆盖工具只计算已有设施的欧氏缓冲，不等同于求解全局最优设施布局，因此候选排序输出应被解释为后续优化或实地核查的输入。

第五步保留数据血缘和可解释原因。每个候选至少应输出候选 ID、社区 ID、原始指标、归一化指标、权重、总分、通过或未评估的约束、使用的 CRS，以及生成该候选的规则。只输出一个总分无法让用户判断它为何排名靠前，也不利于发现输入错误。模型可以把这些字段整理成自然语言建议，但所有分值和排序都必须来自确定性工具。

## 结果验证与解释

候选结果在导出前应检查：候选 ID 唯一；候选几何非空且有效；需要位于目标社区内部时满足空间关系；`service_gap` 和所有归一化指标位于零到一；权重非负且总和为一；`candidate_score` 与公开公式重新计算一致；硬约束失败的候选不进入最终排名；没有被评估的约束在结果和报告中明确出现。

建议同时做权重敏感性分析，例如分别提高需求、人口或可达性权重，观察前几名是否频繁变化。如果候选排名对很小的权重变化高度敏感，报告应说明结论不稳定，不能只展示单一权重下的排序。多个方案分数非常接近时，应把它们作为同一优先级候选交给专业人员比较，而不是制造虚假的精确名次。

最终输出可以是用于 Web 地图的 EPSG:4326 GeoJSON 和一份 Markdown 报告，但距离与约束计算仍必须在适用米制分析 CRS 中完成。缺少土地、规划、水域、道路或风险数据时，系统不能声称候选点具备实际建设可行性；它只能说明这些位置在当前服务缺口与需求指标下值得进一步收集资料和开展现场调查。
