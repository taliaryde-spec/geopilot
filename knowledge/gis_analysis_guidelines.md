# GeoPilot 矢量空间分析指南

本文档是 GeoPilot 项目的本地分析知识基线，用于约束示例场景的计算口径。它不是国家或行业标准；面向真实项目时，应补充项目所在地采用的正式规范并保留来源。

## 坐标参考系与距离计算

EPSG:4326 使用经纬度角度单位，不能直接用于以米为单位的缓冲、距离或面积计算。执行度量分析前，必须根据数据位置选择适用的投影坐标系，并把所有参与计算的图层转换到同一投影坐标系。

GeoPilot 示例数据位于上海附近，项目工具根据数据范围推荐 WGS 84 / UTM zone 51N，即 EPSG:32651。该坐标系的线性单位为米，适合示例范围内的缓冲与面积计算。若数据跨越较大范围或多个 UTM 分带，应重新评估投影方法，不能机械套用 EPSG:32651。

## 服务半径缓冲区

设施覆盖示例使用 `service_radius_m` 作为每个设施的欧氏直线服务半径，单位为米。生成缓冲区前，应检查字段是否存在、值是否为有限数值且全部大于零，并确认输入图层已处于米制投影坐标系。

欧氏缓冲只表达直线距离覆盖，不等同于路网出行时间。河流、道路连通性、出入口和交通方式都可能使实际可达范围与圆形缓冲区不同。需要表达真实可达性时，应改用路网服务区分析。

## 覆盖面积计算

多个设施缓冲区可能重叠。计算总体服务覆盖面积前，应先使用 `union_all` 合并缓冲区，消除重叠部分，避免同一位置被重复计数。

社区覆盖分析的安全顺序是：计算完整社区总面积，生成设施缓冲区，合并缓冲区，将完整社区与合并覆盖范围求交，再按社区标识汇总交集面积。覆盖率公式为：

```text
coverage_ratio = intersection_area_m2 / neighborhood_area_m2
```

求交操作会丢弃完全没有交集的社区，因此必须把覆盖指标按 `neighborhood_id` 左连接回完整社区图层，并将缺失的交集面积、覆盖率和估算覆盖人口填为零。

## 覆盖人口估算

示例使用面积加权的均匀人口密度假设：

```text
estimated_covered_population = population * coverage_ratio
```

该估算假设人口在社区内部均匀分布。住宅、商业、工业和水域分布不均时，结果可能偏离真实覆盖人口。真实项目可引入人口栅格、建筑物或地址点进行更细粒度估算。

## 空间连接与设施计数

`spatial_join` 在当前流程中只用于统计社区面与设施点的空间关系，不参与覆盖面积计算。使用 `how=left` 可保留没有设施的社区，使用 `predicate=intersects` 会把位于边界上的点视为相交。

设施点位于社区外部时，即使它的服务缓冲区跨越边界并贡献覆盖面积，该设施点也不会计入该社区的 `facility_count`。覆盖面积与设施点计数是两种不同指标，必须分别计算后再按社区标识连接。

## 结果验证

覆盖结果在导出前至少应满足以下检查：几何有效；关键指标没有空值或非有限数值；覆盖率位于零到一之间；估算覆盖人口不超过社区总人口；完全未覆盖社区仍保留且覆盖指标为零。

验证失败时不得生成“已验证”检查点，也不得由语言模型补写或猜测缺失结果。应保留失败步骤、错误代码和可恢复的运行记录。

## 输出与解释

Web 地图 GeoJSON 应导出为 EPSG:4326，以便常见 Web 地图库使用。距离和面积计算仍须保留在米制分析坐标系中，报告必须同时披露分析 CRS、导出 CRS、距离单位、面积单位、覆盖公式和人口估算假设。

中间 GeoPackage 用于可复现计算和检查，不应被误认为最终 Web 地图格式。最终报告的数字应直接来自已验证结果数据，而不是由语言模型根据印象生成。
